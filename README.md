# PowerLine CV Project

Streamlit-приложение для автоматического обнаружения элементов и дефектов линий электропередач на изображениях с помощью моделей YOLO. Проект включает демонстрационный ML Dashboard, страницу инференса, сохранение истории детекций и просмотр результатов прошлых запусков.

## Что умеет приложение

- Загружать изображения ЛЭП в форматах JPG, JPEG и PNG.
- Запускать детекцию выбранной YOLO-моделью.
- Отображать bounding boxes, классы и confidence на изображении.
- Показывать сводку найденных объектов и таблицу по классам.
- Сохранять историю детекций локально в `history/`.
- Просматривать прошлые детекции, фильтровать их по модели, искать по имени файла и сортировать.
- Экспортировать историю в CSV.
- Очищать историю после подтверждения пользователя.

## Классы

Проект работает с классами исправных элементов и дефектов ЛЭП:

| Группа | Классы |
| --- | --- |
| Исправные элементы | `vibration_damper`, `festoon_insulator`, `polymer_insulator`, `traverse`, `safety_sign` |
| Дефекты и риск-факторы | `bad_insulator`, `damaged_insulator`, `nest` |

В таблицах метрик также используются имена классов из разметки/валидации: `safety_sign+`, `festoon_insulators`, `polymer_insulators`.

## Модели

В проект добавлены три веса YOLO:

| Модель | Назначение | mAP50 | mAP50-95 | Размер |
| --- | --- | ---: | ---: | --- |
| `YOLOv12n` | Быстрая компактная модель | 0.834 | 0.573 | 2.6 млн параметров, 6 МБ |
| `YOLOv12s` | Баланс скорости и качества | 0.854 | 0.591 | 9.3 млн параметров, 20 МБ |
| `YOLOv12L` | Тяжелая и наиболее точная модель | 0.883 | 0.681 | 26.45 млн параметров, 54 МБ |

Файлы весов лежат в директории `models/`:

```text
models/
  yolo12n.pt
  yolo12s.pt
  yolo12L.pt
```

## История детекций

После запуска детекции результат сохраняется в файловое хранилище:

```text
history/
├── history.csv
├── images/
│   ├── original/
│   └── predicted/
└── results/
    └── <detection_id>.json
```

Для каждой записи сохраняются:

- уникальный ID;
- дата и время детекции;
- имя исходного файла;
- название модели;
- количество найденных объектов;
- исходное изображение;
- изображение с отрисованными bbox;
- JSON с классом, confidence и координатами bbox.

Директория `history/` добавлена в `.gitignore`, потому что это runtime-данные приложения.

## Локальный запуск

Рекомендуемая версия Python: 3.11.

1. Создать и активировать виртуальное окружение:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

2. Установить зависимости:

```bash
pip install -r requirements.txt
```

3. Запустить Streamlit-приложение:

```bash
streamlit run app/main_page.py
```

После запуска откроется многостраничное приложение:

- `Главная` - описание проекта, модели, метрики и параметры обучения;
- `Детекция` - загрузка изображения, выбор модели, запуск инференса;
- `История` - просмотр, фильтрация, экспорт и очистка сохраненных детекций.

## Запуск FastAPI

В проекте также есть простой FastAPI backend:

```bash
uvicorn main:app --reload
```

Основной endpoint:

```text
POST /predict
```

Параметры:

- `file` - изображение;
- `model_type` - `fast` или `accurate`.

## Streamlit Cloud

Проект подготовлен к деплою в Streamlit Cloud.

Настройки:

- Main file path: `app/main_page.py`
- Python: `3.11`
- Python-зависимости: `requirements.txt`
- apt-зависимости: `packages.txt`

Файлы для деплоя:

```text
runtime.txt
.python-version
packages.txt
.streamlit/config.toml
```

Важно: история детекций в Streamlit Cloud хранится в локальной файловой системе контейнера. Это подходит для демонстрации, но не является постоянным хранилищем. После перезапуска или редеплоя приложения сохраненная история может быть потеряна. Для production-сценария историю лучше вынести во внешнее хранилище: S3-совместимый bucket, базу данных или отдельный backend.

## Ограничения текущей версии

- Инференс на Streamlit Cloud выполняется на CPU, поэтому тяжелая модель `YOLOv12L` может работать заметно медленнее, чем локально на GPU.
- Локальная история детекций не является постоянной при облачном деплое.
- Модели загружаются лениво при первом запуске детекции, поэтому первый инференс может быть дольше последующих.
